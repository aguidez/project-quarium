Playtesting UI through the Roblox Studio MCP:

- `screen_capture` images are scaled down (e.g. 1519x1080 for a 1621x1152 viewport): pixel positions read on a capture do NOT match `user_mouse_input` x/y. Prefer `moveTo` with `instance_path` ("LocalPlayer.PlayerGui.ReactUi.Modal.Panel.Body.Header.Close"; side buttons: "…ReactUi.SideButtons.Quests"), or read `AbsolutePosition`/`AbsoluteSize` via execute_luau (Client) and click their centre.
- @rbxts/react names instances by the `key` of the host element itself; a key put on a function component is not used if the component's root element has its own key (e.g. quest tabs are named by their label "☀️ Daily").
- execute_luau resets the camera to Custom, so captures right after it may show a stuck/odd camera; the 2.5D focus view only comes back by leaving and re-entering the focus zone.
- Plugin `require` gets separate module copies: drive the game through remotes (client FireServer, or Server datamodel firing remotes to clients) instead of calling services.
- A running playtest doesn't pick up Rojo changes: stop/start play after `npx rbxtsc`.
- Fish no longer die of hunger (they turn Weak and fart 1$ bubbles), so long tests keep their fish.
- screen_capture does NOT render BillboardGuis parented to PlayerGui (hunger badges, money popups): verify them by script (Enabled, text), not by capture.
- **Check that Rojo is really syncing** before trusting a playtest: the Studio plugin can be disconnected while `rojo serve` runs (the place then runs old code). Grep the script's `.Source` from execute_luau for a new *code* string (roblox-ts strips comments, so a `// TEMP TEST` marker is never in the Luau); if missing, ask the user to reconnect.
- **Camera for play captures**: execute_luau resets the camera to Custom when it returns. To capture a precise view in play, spawn a RenderStepped loop (task.spawn, ~10 s) that keeps `CameraType = Scriptable` and the CFrame, return, then screen_capture.
- **Blank captures**: Studio sometimes renders no 3D (only the view cube / the UI) for a while, in Edit too. Build in Edit by script anyway and check visuals in a playtest later (it came back on its own).
- **Tests that change the user's save** (rebirth...): back up the raw key first (`DataStore:GetAsync` in Edit, keep a copy in the scratchpad), test, stop play, wait for the final save, then `SetAsync(key, backup, {userId})` and check it.
- **Solo playtests have one player**: features between players (likes…) need a `// TEMP TEST` bypass (e.g. allow self-like in Studio) to test the server path, restored afterwards.
- **Saves (ProfileStore)**: Studio API access is on for this place (ProfileStore prints "Roblox API services available"). Check the saved profile with `DataStoreService:GetDataStore("PlayerData_v1"):GetAsync("Player_<UserId>")` (`.Data.player`, `.Data.tank`, `.MetaData.ActiveSession`); GetAsync is cached ~4 s, so re-read after a wait before concluding a save failed. Stop/start play = leave/rejoin test; the test account's progress persists between playtests.
- To get the 2.5D view back after execute_luau broke the camera: click LocalPlayer.PlayerGui.FocusUi.Back, then teleport out of / back into the zone with task.delay inside a script that returns immediately.

- **Load test of the bone swim (V1.1.14, no code change)**: from the Server datamodel copy the templates of
  `ServerStorage.Assets.Fish` (tags removed) into a `ReplicatedStorage` folder; from the Client clone 25 per tank into
  each Aquarium's `Water` box (anchored, tag `Fish`: FishRigController poses them). Hold the camera with a RenderStepped
  loop inside the same execute_luau (the Assistant resets a Scriptable camera after each call), 4–8 s to settle, then
  5 s of `HeartbeatTimeMs` / `RenderCPUFrameTime`; compare by removing the `Fish` tag (they stop) and resetting the
  bones' Transform. A first sample that gets 1 frame in 5 s is a stalled render: run it again.
- **Perf measurements**: Studio caps at 60 fps, and at 15 fps when its window loses focus (steady 66.7 ms frames = that cap, not load; got fooled once). Use `Stats.HeartbeatTimeMs` (script time) and `Stats.RenderCPUFrameTime` / `RenderGPUFrameTime` averaged over a few seconds instead of fps. Solo play has one Player: to load other tanks, a temporary `// TEMP TEST` harness spawned real FishService fish with the player as owner but another tank (excluded from saves and quest callbacks), backed up and restored afterwards.

- **UI V2 instance paths** (2026-10-30): a kit Button3D's clickable part is its `Face` child: side buttons "…ReactUi.SideButtons.Quests.Button.Face", panel close "…ReactUi.Modal.Panel.Window.Close.Face".
- **Preview a component with fake data** (states the test account can't reach: quest cards, rewards): in a Client execute_luau, `require(ReplicatedStorage.rbxts_include.node_modules["@rbxts"].react)` and `["react-roblox"]` (the ModuleScript itself, not `.src`), require `LocalPlayer.PlayerScripts.TS.ui.<File>`, `createRoot` on a temporary ScreenGui (DisplayOrder 50) and render it with fake props; destroy it after the capture. Display only, nothing reaches the server. Set the preview ScreenGui's `ZIndexBehavior = Sibling` like ReactUi (the default Global hides titles, icons and bars under the card faces). To preview config that doesn't exist yet (new quest kinds), mutate the plugin's own copy of the shared module (e.g. `QUESTS`, `STORY_LINES`) before requiring the panel: the game never sees it.
- **Dev chat commands** (Studio, owner only; /datareset, /nextfrench, /incubators, /pass, /boost <min>, /speed <x>, /passes off|on): send them from a Client execute_luau with `TextChatService.TextChannels.RBXGeneral:SendAsync("/incubators 2")` inside `task.spawn` (a direct call can time the request out).

- **Gamepasses in Studio** (2026-10-30): Roblox counts the game's creator as owning every pass of the game, so the owner's playtests show all passes OWNED and active. Use `/pass <GamePass>` (session only) to see the buyer's side. `GetProductInfo(id, Enum.InfoType.GamePass)` returns `IsForSale = false` / no price until the owner sets a price on the Creator Dashboard.
- **Rojo half-syncing** (2026-10-30, macOS): with the plugin "connected", Studio got some edited files but not others nor any new file. Restarting `npm run serve` and reconnecting the plugin fixed it. Check a new file *and* an edited one before a playtest.
- **Clicking a side button reliably** (2026-10-31): `moveTo` with an instance path like "LocalPlayer.PlayerGui.ReactUi.SideButtons.Companions" clicked the wrong button (the names hold spaces, e.g. "Fish Index", and the path resolution misses). Read `AbsolutePosition` / `AbsoluteSize` of the buttons with execute_luau (Client) and click their centre with x / y: with the ScreenGui's IgnoreGuiInset on, those are the mouse coordinates. Same for a panel's `Close` (ReactUi.Modal.Panel.Window.Close).
- `require()` of a game module from execute_luau gives a separate copy: to read the live state, listen to `SyncPlayerData` / `PlaySfx` from a Client script, or read replicated attributes.
- **Driving an event test from execute_luau** (2026-11-02, UFO night): fire `ReplicatedStorage.Remotes.RequestAction:FireServer("AdminStartEvent", "<EventType>")` (and `"AdminStopEvent"`) from a Client script (the admin panel's actions, Studio only). To click the panel's buttons, use the viewport coordinates of their `AbsolutePosition` (here 1621 × 1152), not the capture's (1519 × 1080). Dev chat commands can be sent with `TextChatService.TextChannels.RBXGeneral:SendAsync("/ufo alien")` **inside task.spawn** (a direct call yields until the request times out). To catch a short visual (a 1.5 s beam), loop in a Client script until the attribute flips (`Beaming`), return, then screen_capture at once; or set the attribute locally on the client for a few seconds (the client's own copy). Enter the 2.5D view by teleporting the character 40 studs out, then into the focus zone (frame * (0, 4, −15)) inside a task.delay so the script returns first.
- **Measuring a music event's coins** (2026-11-02, Island Breeze): fish are client-rendered (the tank's `Fish` folder is empty on the server), but every coin lands in the aquarium's `Coins` folder: connect `ChildAdded` from a Server script, store `GetServerTimeNow()` in `_G`, read it back in a later call (log the event's `EventStartsAt` attribute too). Coins of fish sharing an interval drop together, so bursts of 10–20 coins on one frame are normal. Reset `/speed 1` first (the owner's test speed chip speeds the regular coins, not the beats).
- **Finding a track's BPM and first beat** (2026-11-02): in the Edit datamodel, `AudioPlayer` (Asset = the id, Volume 1, no output device: silent) → `Wire` → `AudioAnalyzer`; wait for `IsReady`, `Play()`, sample `TimePosition` and `RmsLevel` on every Heartbeat for ~30 s. Keep the top 5 % rises of RMS (onsets) and fold their times modulo 60 / BPM: the vector strength peaks at the real tempo and its angle gives the beat offset; folding modulo 4 beats shows the accented beats. With Volume 0 the analyzer reads nothing; a `Sound`'s `TimeLength` gives the length once `IsLoaded`.
- **Comparing variants of a server-made billboard** (2026-11-02, title nameplates): one player can only wear one title at a time, so from a Server execute_luau watch the head's `ChildAdded` and `Clone()` each new `PlayerTitle` onto invisible anchored parts stacked in front of a backdrop (StudsOffset zeroed), while a Client script cycles `/lbtitle <Board> <rank>` (2.5 s apart); then capture all of them at once. World billboards (not in PlayerGui) do show in captures.
- **Previewing a world board with fake data** (2026-11-02, leaderboards): from a Server execute_luau, `FireClient` the real remote (`ReplicatedStorage.Remotes.LeaderboardSync`) to the player with a fake payload, in a `task.spawn` loop every second (the service's own push replaces it every 30 s; stop the loop with a `_G` flag). Display only, nothing is written. The Edit camera may be left at FieldOfView 20 by an earlier focus-camera check: captures then look zoomed in; set it back to 70. A SurfaceGui list scrolls with `user_mouse_input` scrollDown at the board's viewport point (`Camera:WorldToViewportPoint`, or the capture point x viewport / capture width).
- **Previewing the ReplicatedFirst loading screen** (2026-11-02, V0.55): it only lasts ~3 s in a playtest (a capture right after `start_stop_play` does catch it, near the end of the fill). To study it at a fixed progress, paste the compiled `out/first/LoadingScreen.client.luau` into an Edit execute_luau, minus the progress section, with `player` set to nil and the ScreenGui parented to `StarterGui`; RenderStepped runs in Edit, so it animates. Drive `target` from a `_G` value in a `task.spawn` loop and stop it with a `_G` flag (destroy the gui). Zoom on the saved capture with a jimp crop to look for seams.
- **Chat window not in captures** (2026-11-03, chat title tags): screen_capture shows the 3D view, PlayerGui and the chat bubbles, but not the CoreGui (top bar, chat window). To check what a TextChatService callback writes, `require` the compiled controller ModuleScript from `LocalPlayer.PlayerScripts` in a Client script and call its method directly (`require(mod).ChatTitleController:getTag({ UserId = lp.UserId })`); `/lbtitle <Board> <rank>` gives a leaderboard title to test with.
- **Testing a save at a given progress without touching the owner's** (2026-11-03, the alpha): in Edit, read the owner's profile (`PlayerData_v1`, key `Player_<UserId>`, the whole ProfileStore table), deep-copy it with `HttpService:JSONEncode/JSONDecode`, edit `Data.player` (rebirths, money, hatched, Ocean Points and claimed milestones, quest lines, companions, cosmetics; empty `Data.tank`), set `Data.stats.testSpeedUsed = true` (off the leaderboards and analytics) and `MetaData.ActiveSession = nil`, `SetAsync` it into a test store with `{userId}`; point `STORE_NAME` at that store (`// TEMP TEST`), build, check Rojo synced it, play. Afterwards restore `STORE_NAME`, rebuild, check the sync, then `RemoveAsync` the test key once its session lock is gone. The owner's profile is at rebirth 5: an early stage needs such a copy. The intents (`RequestAction:FireServer("BuyEgg" / "OpenEgg" / "ClaimQuest" / "Rebirth", …)`) drive the server faster than clicks; a side button often needs a second click right after a panel closed.
- **A billboard missing in the 2.5D view only during an event** (2026-11-03, the UFO sleep bubble): the focus camera stands back to frame the tank (FOV 20): ~133 studs during a UFO night (its headroom), less otherwise. A billboard on a fish or in the tank with `MaxDistance` 120 vanishes then (`AbsoluteSize` 0, 0 even with AlwaysOnTop): give tank billboards `math.huge` like the hunger badges. Check by measuring `AbsoluteSize` from a Client script: MCP captures of a playtest may come from another camera.
- **Playing the onboarding on a fresh profile** (2026-11-03, the food reserve): point `STORE_NAME` at an empty test store (`"PlayerData_<Name>Test"; // TEMP TEST`), build, check the sync, play: the owner starts from step 1. Drive it with intents (`BuyEgg "Common"`, then `OpenEgg "Common"` every second until the frozen coin shows, `Interact:FireServer("CollectCoin", coin)`), then wait for the Feed step. Afterwards stop, restore `PlayerData_v1`, rebuild, check the sync, `RemoveAsync("Player_<UserId>")` in the test store from Edit. Such a profile has no `testSpeedUsed`: it does send one onboarding funnel to the Creator Dashboard. Real clicks with `user_mouse_input` use viewport coordinates (the capture is scaled down, see above): a click "above the water" in capture pixels lands outside the tank and silently does nothing. A 0.7 s UI flash is shorter than a capture's delay: record it from a watcher loop started in a Client script (texts / colours into a local attribute), click, then read the attribute.
- **Previewing the UI on a phone** (2026-11-04, V0.60.8): Studio's device emulator can't be driven by MCP. TEMP
  harness (`// TEMP TEST`, reverted with `git checkout` + a grep for TEMP TEST): `screenScale.getViewportSize` returns
  `new Vector2(844, 390)` (iPhone landscape, in points); App's `computeBarPlacement` uses left 120 / right 844 as the
  phone's topbar room; UiController mounts the React root in an `Inner` frame (Size 1, 1) inside a `Phone` frame
  844 × 390 (ClipsDescendants, red UIStroke) holding a UIScale = viewport width / 844. React clears its container's
  children, so the UIScale must sit on the outer frame; and the viewport is 1 × 1 during onInit: set the UIScale from
  a Client execute_luau once in play. The Panel's fit reads on-screen pixels: divide its AbsoluteSize by the
  magnifier during the test. FocusUi and the toast stay outside the box (judge them by their AbsoluteSize). The 3D
  focus camera frames the real viewport, not the box. Mouse clicks: `user_mouse_input` x / y = the `AbsolutePosition`
  values of ReactUi elements (no topbar offset to add).
- **Coordinates in the topbar row** (2026-11-04, the sound control): `AbsolutePosition` counts from under Roblox's
  topbar inset even in a ScreenGui with IgnoreGuiInset, so an element in the topbar row has a negative Y (-29 for the
  sound button). `InputObject.Position` uses the same origin: compare them directly (adding `GetGuiInset` shifts a
  slider by the topbar's height). `user_mouse_input` x / y take the same values, but a negative y can't be sent:
  click topbar elements with `instance_path` (e.g. "LocalPlayer.PlayerGui.ReactUi.SoundControl.2.Face"; an unkeyed
  React child is named by its index).
