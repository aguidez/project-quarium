Adding a fish species / coin / egg (done 2026-10-29 for Clownfish, Zebra Danio, Flame Gourami, Superior & Freshwater eggs):

- **3D**: Studio MCP `generate_mesh` (async, several in parallel). Results land in Workspace tagged `Assistant-<id>`. Generic prompts often miss (puffer-like fish, "macaron" gem, tiny ingot): ask for "side profile, long slender body" and give a bbox with the real proportions; check with screen_capture before building templates.
- Templates: fish in **ServerStorage.Assets.Fish** and variant textures in ServerStorage.Assets.FishVariants since V0.37 (2026-10-30; server/fishAssets copies a species to ReplicatedStorage.Assets.* while one swims, clients clone that copy), coins in ServerStorage.Assets.Coins (place file, NOT Rojo → remind the user to save the place): invisible anchored root ("Body" for fish, "Hitbox" ×1.25 and CanQuery for coins) + welded "Mesh" MeshPart; convert TextureID into a SurfaceAppearance ColorMap (the client tints SurfaceAppearance for weak fish). Fish head toward -Z.
- **Event fish** (ServerStorage.Assets.EventFish, tag EventFishTemplate + attr EventType): same layout. LanternFish (2026-10-29): `segmentation: "none"` gave one clean MeshPart; glowing bits are separate welded Neon parts (its "Lure") that the client lights, so they can fade apart from the body. Dark meshes: tint the SurfaceAppearance `Color` rather than re-generating.
- **Recoloured textures (fish variants, 2026-10-29)**: a game script can't set SurfaceAppearance.ColorMap (only `ColorMapContent` getter), so variants are pre-made SurfaceAppearance instances (ReplicatedStorage.Assets.FishVariants, tag FishVariantAppearance) swapped by the client. Getting a texture OUT of Studio: `AssetService:CreateEditableImageAsync(Content.fromUri(id))` → `ReadPixelsBuffer` (no `Resize`: downsample by strips in Luau) → `HttpService:RequestAsync` POST to a local node server — needs `HttpService.HttpEnabled = true` for a moment (turn it back off!). `AssetService:CreateAssetAsync` is "not available yet", so uploads go through `upload_image` from a local http server. Multiply tints (SurfaceAppearance.Color) can't recolour red fish: use hue rotation (tools/fish-variant-recolor.js). Freshly uploaded images render white for a minute.
- **2026-10-29 batch (Angelfish, Discus, coins, NeonCoral theme)**: 11 async generate_mesh at once all failed ("Unable to generate Model"); 3 at a time works, and `maxTriangles` works (5000 → ~3.6k vertices). Generated MeshParts come with head / front on local -Z for fish (template Mesh at identity) but objects (coins) show their front on local -X: rotate the template Mesh -90° Y so it faces the glass (coins face template -Z). Sticker icon sheet: 3 cols × 4 rows filling a FOV-20 view, backdrop SurfaceGui needs PixelsPerStud ~4 (default 50 on a big part renders nothing); white backdrop reads ~223 grey, fine for the tool. Rotate fish yaw -105° for the 3/4 head-right look.
- **2026-10-30 (French Fish, croissant)**: "cute cartoon fish, side profile" gave an upright front-facing chibi creature; "fish swimming horizontally, side view, oval body longer than tall, forked tail fin at the back" gave a real fish profile. Icon sheet: the black/white SurfaceGui backdrop rendered nothing this time; a plain backdrop Part (black SmoothPlastic, then white **Neon**) with post effects off works with the sticker tool (cols 1, rows 1, rowTop 0, rowH 1080). Check icons as a moderator at 256×160: in pure profile the scarf was a red horizontal tube at mouth level, so the icon uses a front 3/4 view (yaw 60°). A food-shaped coin can read as another item (croissant ~ the pink Shrimp food): tint it with SurfaceAppearance Color.
- **2026-10-30 (M2: Catfish, Blue Tang, Baby Sunfish, 3 coins, 2 eggs)**: "cute cartoon X" and the bare word "catfish" gave front-facing chibi creatures (a literal cat); "fish swimming horizontally, side view, ... stylized game art" worked; generate 2 candidates when a feature is risky and drop the one with a thin barbel pointing forward. The `size` param is not honoured (meshes come ~2 studs): set the template size yourself. Texture pull that works: EditableImage → box-downsample to 512 by strips → base64 in Luau (buffer) → POST text/plain to a node server (scratchpad texserver.js also serves PNGs for upload_image) with HttpEnabled on only during the call. Icon sheet: 3 cols × 4 rows, FOV 20, camera 73.7 studs away, cells 12.2 × 6.5, fish yaw +75° (head screen-right, 3/4 front), black SmoothPlastic then white Neon backdrop Part, PostEffects + Atmosphere off then restored; deselect (Selection:Set{}) or the axis gizmo shows. New uploads render white for ~40 s.
- **Rebirth / progression playtests without touching the owner's save**: temporarily point DataService STORE_NAME at a test store and preset the profile in sanitizeSave (all `// TEMP TEST`), revert after.
- Writing a player's DataStore key from execute_luau (restoring a test backup) was denied by the auto-mode classifier: ask the user to restore it, or to allow it.
- **EditableMesh budget is small** (Studio hit it at ~16 meshes / ~46k vertices): FishAnimationController keeps 2 swim variants per fish type, builds the slow variant lazily, frees idle rigs and retries failed ones. Keep new fish meshes ≤ ~4–5k vertices. **Measured 2026-11-01**: the budget counts *triangles* (~81k on the owner's PC; fill it with copies of one mesh in a Client execute_luau, after moving the camera away so the LOD frees every rig); on a full budget `CreateEditableMeshAsync` returns nil instead of throwing; Studio Edit has no budget (probes there are meaningless). The long-term fix is ROADMAP_V1.1.md (Blender skeletons). **Simulate a phone** (V0.45 tests): in a Client execute_luau, send the player far away with a Scriptable camera for 20 s (rigs released after 15 s), hold ~20 Golden Guppy EditableMeshes (≈50k triangles), bring the player back, wait, count fish with `Animated` vs a moving mesh `Weld` (sway); read `LocalPlayer:GetAttribute("SwimTriangleBudget")`. Pitfall met: a room check done *before* waiting for the build lock let two species overcommit, and each refusal then lowered the budget further (down to the 10k floor): check and build under the same lock. `Destroy()` frees an EditableMesh's share instantly.
- **2D**: fish icons are stickers (tools/fish-sticker-icons.js from Studio captures; the first flat SVG icons and fish.build.js were removed in V0.50). Egg sprites in design/ui/eggs.build.js → SVG → FigCraft `file.import` → `file.export` png scale 2 (or resvg) → serve the folder on 127.0.0.1 with a small node server (background task, stop it with TaskStop, never kill all node.exe) → `upload_image` → ids in src/client/ui/theme.ts.
- **Playtest shortcut**: stand at aquarium CFrame * (0, 5, -14) (front focus zone, NOT inside the tank), drive the onboarding via remotes (BuyEgg/OpenEgg, Interact CollectCoin/DropFood). Fish no longer die of hunger (they turn Weak after 45 s and fart 1$ bubbles): feed them only if the test needs coins. Temporarily raise ONBOARDING_REWARD / egg odds with a `// TEMP TEST` marker and restore them.
- **Raster edits** (no Python needed): jimp 0.22 is a devDependency of the project, small node scripts (crop to inspect with Read; Read shows PNGs without their alpha, composite on a pink backdrop to check a cutout). Cutting a logo out of a picture: flood the background from a search box's border, stopping at the logo's dark outline, keep the big pieces (tools/loading-art.js). **Erasing a baked element over a texture** (a loading bar over sand, 2026-11-02): mirrored copies, quilting and Poisson blends all stayed visibly patched up close; ask the owner for the picture without it (they regenerate it, or use a generative eraser such as Windows Photos > Edit > Erase) instead of spending time on it.
- A freshly uploaded image may not render on the very first frames of a playtest: show UI on a plain colour and fade the image in after PreloadAsync.
- Economy: `node tools/economy-sim.js` (in the repo since the rebirth, 2026-10-29; average player = collect 0.5, calibrated on the old "6 fish at ~1h" notes). Balance notes in eggs.ts / rebirths.ts.

- **UI icons without FigCraft** (2026-10-30): `tools/pass-icons.js` draws icons as SVG in the V2 style (14 px outline at 512, gradient light → base, white gloss stroke, sparkles) and renders them with `@resvg/resvg-js` (devDependency, prebuilt on Windows / macOS), plus a `_sheet.png` showing each at its in-game size for review. No text in uploaded icons: the values ("x2", "+50%") are kit Chips drawn by the game.
- **2026-10-31 (M4: Lanternfish, Nautilus coin, Swordfish, Water Hen, Mariana Trench)**: "fish swimming horizontally, side view, ... no lure" gave a clean Lanternfish at once; the first nautilus prompt ("nautilus spiral seashell coin") gave an open clam, "nautilus shell, a single coiled spiral snail-like seashell seen from the side, round flat disc" worked. A "dark basalt rock spires" mesh looks far better than rotated Basalt Parts. **Icons of variants before any upload** (CLAUDE.md §7.4): pull the texture out (EditableImage → 512 → base64 → POST to a scratchpad node server), recolour offline, send the result back as base64 RGBA (`HttpService:GetAsync`, mind the "=" padding when decoding into the buffer), write it into an `AssetService:CreateEditableImage`, remove the clone's SurfaceAppearance and set `MeshPart.TextureContent = Content.fromObject(image)`: the sticker sheet then shows the Anomaly / Shiny looks without uploading anything. Ghost = SurfaceAppearance Color lerped 55 % to (185, 235, 255) + Transparency 0.5 (fishLook.ts). One species: sheet `"cols": 1, "rows": 4, "rowH": 270` (fish scaled to 10 studs, rows 5.5 studs apart, camera 62.4 studs away at FOV 20). Companions sometimes render untextured on the first capture: capture again. Egg sprites can be rendered with resvg (200 px wide) instead of FigCraft. `require()` of a game module from execute_luau gives a separate copy (empty data): read the state from the client (`SyncPlayerData` listener) or from replicated attributes instead.
- Theme water: since V0.40 every theme's `Style/` has a `Water` part (copyStyle copies Transparency too), so one theme can tint its water without leaving it on a tank that changes owner.
- **2026-10-31 (M5: Lionfish, Dragonfish, Jellyfish, Volcanic Temple)**: any prompt with the word "dragon" (or "dragon-like", "dragon's mane") gave an **upright, seahorse-like creature** (C-shaped body, horn or mohawk crest) that can't swim with the fish rig, even with "swimming horizontally"; "betta / veil fins" made the tail droop vertically; "koi with whisker ribbons" gave barbels at the mouth (moderation risk). What worked: "fish swimming horizontally, side view, long serpent-like body ... frilly mane fin from the head down the whole back ... lying flat and straight", then a gold SurfaceAppearance Color tint. The first lionfish ("cute lionfish ... fan fins") had a crumpled face: "fish swimming horizontally, side view, oval body ... zebra stripes ... fan-shaped pectoral fins, no spines" was clean. A "volcanic rocks with glowing magma cracks" mesh came out as pale rocks ringed around a glow = **a campfire** (CLAUDE.md §7): build magma as flat Neon veins on the sand instead. Generated temple pieces may carry rune-like glyphs that read as letters: keep them out of uploaded icons.
- **`Model:ScaleTo` leaves a scale factor on a template**: CompanionService spawns companions with ScaleTo(0.05) then tweens back to scale 1, i.e. the template's *original* size. Build templates at the right size (resize the MeshPart and the Body), never ScaleTo them (check `GetScale() == 1`).
- Generated meshes come with `TextureID`: a MeshPart's Color doesn't tint it. To tint a prop (theme decor), move the texture into a SurfaceAppearance (ColorMap) and set its Color.
- **2026-11-01 (M6: Husky Dogfish, Bunny Shark, Mini Leviathan, Crystal Caverns, Cosmic Sanctuary)**: "hammerhead" never works (5 tries: hammer on top of the head, on a stalk, or a plain shark); the owner dropped it for a **Bunny Shark** ("kawaii shark with bunny features ... dorsal fin, forked shark tail, long floppy bunny ears, closed smile"). The owner judges **name ↔ look consistency**: a "dogfish" with a wolf head on a shark body read as a shark, a round bunny without shark fins didn't read as a shark; show 3–5 candidates side by side (plus a front view on request) before building anything. "husky dog head on a plump fish body" gave the approved dogfish. A mesh that comes out upright (C-shaped serpent) is usable once **pitched ~30° about X inside the template** (FishAnimationController deforms in mesh-local Z: never yaw a mesh 90° in its template, only pitch / roll slightly); generated meshes so far all had their nose at mesh-local −Z (check with `CFrame:VectorToObjectSpace`). Scale templates by their max dimension (6 studs for Mythics), never by Z alone (a tall mesh got huge). Sticker sheet: scale each fish by `min(6.2 / Z, 4.1 / Y)` so tall ears / crests stay inside their 5.5-stud row.
- **Lighting during icon captures**: the sheet setup parents the Atmosphere to nil and disables the PostEffects; if Studio is saved / closed before the restore, the Atmosphere is gone for good (no local place file: only the cloud version history). On 2026-11-01 it had to be recreated by hand (Density 0.3, Offset 0.25, Color c7e1f0, Decay 6a8ca5, Glare 0.2, Haze 1; SunRays, Bloom, BeachGrade on, DepthOfField off). Prefer moving it to ServerStorage (survives a save) and restore right after the two captures.
- **Titles and decor (V0.44)**: a decor cosmetic is a model in `ServerStorage.Assets.Decor` (tag `DecorTemplate`, attr `Cosmetic`, PrimaryPart its Mesh) placed at its `DECOR_SLOTS` entry (tank-local X / Z, Y = the sand top) by AquariumService with the theme decor; a title is just a `COSMETICS` entry ranked in `TITLE_ORDER` (TitleService shows the best one).
- **2026-11-02 (V0.49: UFO + Alien Fish)**: three UFO candidates (classic silver saucer with green lights, pastel mint with a pink dome, tall violet with portholes) and three alien fish ("fish swimming horizontally, side view, ... alien fish ..., antennae with round tips on top of its head ..., nothing in front of the mouth"); the owner picked the classic saucer and the lime green fish with two antennae. **A generated fish can have its face on one side only**: the chosen alien shows big eyes and a smile on its right side and a single plain eye on the left; always capture both sides before showing candidates. Its sticker uses the face side (yaw −125° with the camera on +Z looking −Z). An event prop that isn't a fish (the UFO) still goes in `Assets.EventFish` (tag EventFishTemplate, attr EventType) with the Body + welded Mesh layout, sized by its max dimension (8 studs). Templates were rebuilt from the candidates' MeshParts (`MeshPart:Clone()`, size set directly, TextureID moved into a SurfaceAppearance), never from a ScaleTo'd model.

## Meshes the group owns (V0.60.5)

The game belongs to the owner's group (SecretVerse Fish, 815548702); the owner's account DOT_Pinpin is a Manager there
(rank 254; the group's owner is Secret_Lokii). A mesh the clients animate (`CreateEditableMeshAsync`: the fish, the
Swordfish, the event guests) must belong to the group. Meshes made from Studio (`generate_mesh`) belong to DOT_Pinpin:
re-upload them as the group. What works (V0.60.5, the 24 animated meshes):
1. **Export** from the place (Edit): `node tools/obj-receiver.js design/meshes` in the background; in an execute_luau,
   `HttpService.HttpEnabled = true` (off on this place: put it back after), `CreateEditableMeshAsync(Content.fromUri(
   part.MeshId))`, write `v` / `vt` (**1 - V**) / `vn` / `f v/vt/vn` lines (ids mapped to 1-based indices) and POST
   them to `http://127.0.0.1:34999/<Name>.obj` in ~500 KB pieces (header `x-append: 1` after the first). Windows
   file names ignore case: two meshes named Lanternfish / LanternFish overwrite each other, rename one.
2. **Upload**: `npm run group-mesh-upload design/meshes/<Name>.obj ...` (OBJ to GLB pre-rotated 180° around Y, upload as
   a group Model, grants to DOT_Pinpin and to the universe with dependencies); it prints { name: modelId }.
3. **Swap** (Edit): `game:GetObjects("rbxassetid://<modelId>")[1]` holds one MeshPart with the group's mesh; check it
   against the old one (same face count, nearest-vertex distance < 0.001), then on the template's `Mesh`:
   `ApplyMesh(source)`, put back its `Size` and `CFrame` (the SurfaceAppearance stays). Destroy the loaded model.
   Then ask the owner to **save and publish** the place (ServerStorage.Assets is in the place file, not Rojo's).

Dead ends: `AssetService:CreateAssetAsync` ("not available yet", Edit and playtest), `AssetImportService` (not
exposed), sharing the owner's meshes with the universe (accepted, useless) or with the group (CannotManageSubject),
uploading as the group with the owner's personal key (unauthorized), loading a group model in Studio before it is
granted to DOT_Pinpin ("User is not authorized to access Asset"; `grantToDependencies` only works for the Universe
subject). A GLB uploaded without the pre-rotation lands turned 180° (X and Z negated: the fish would swim backwards).
The exported OBJ files stay as the source (design/meshes, manifest.json: template and old mesh id).
